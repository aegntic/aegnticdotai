That leaves room to look at the workflow rather than the next model. Pick the last task that needed avoidable intervention. Where did it go wrong? A lost constraint, an ignored tool error, a misleading completion message, or a test that wasn’t checking the important thing?

Turn that failure into something repeatable. Then change the smallest part that addresses it. Save the case so the next prompt or model update has to get past it too.

I’d also look for repeated work. Two agents researching the same source isn’t automatically useful redundancy. Five logs that must be read to find the current state aren’t necessarily observability. Sometimes they are just five logs.

Remove the step that isn’t helping. Tighten the handoff that keeps losing context. Fix the check that reports success too early. Those changes won’t produce a dramatic launch screenshot, but they can make tomorrow’s task less annoying.

The archive doesn’t need to invent an event to fill a date. There is enough actual work between announcements. Some weeks the worthwhile change is getting the existing system to behave properly.
