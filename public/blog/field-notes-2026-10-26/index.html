Search for the skills

The October correction was simple: find the existing work first.

Field NotesRetrospective

Retrospective field note for 2026-10-26, reconstructed on 16 November 2026. Historical project discussions establish intent, not a claim that proposed work shipped.

On 20 October, I asked to search AEGNTIC’s GitHub for skills. The conversation started turning into skill creation. I corrected it: this was a search for existing skills.

Then I asked for a more comprehensive search across skills, plugins and custom MCP work. The scope grew within discovery. It did not become permission to invent another subsystem.

The difference is obvious, yet it is exactly the kind of mistake that makes an assistant expensive to supervise. A tool name or familiar workflow takes over from the verb in the request.

Read what is already there. Check its purpose, dependencies and supported environment. Distinguish a reusable procedure from a prompt tied to one old conversation. Report gaps when nothing fits.

The archive preserves the correction, not a verified list of adopted components. New work can follow if it is needed. First finish the search. An agent should be capable of taking initiative without turning a straightforward discovery task into a fresh project.
