Can another worker finish this?

Save enough state that an interrupted task can be resumed without guesswork.

Field NotesRetrospective

Retrospective field note for 2026-02-16, reconstructed on 16 November 2026. The archive date is not a claim of publication at the time.

Close the session halfway through. Can another worker find the draft, understand the last decision and carry on?

If the answer is no, the task is leaning too heavily on the conversation. Save the actual work. Keep originals separate from generated versions. Record the command that failed and the next thing to check. Nobody should need to reconstruct the project from a cheerful progress message.

Shell access makes this more important. There may be a process still running, a file already written or an action whose result never came back. Inspect before retrying. Repeating a read is one thing; sending the same message twice is another.

Skills should help the next worker do the specific job. Inputs, steps, checks. A huge instruction file filled with general advice can bury the one requirement that matters.

The workspace is part of the deliverable. A neatly organised partial result is worth more than a long explanation of everything that would have been completed if the session had continued.
