AEGNTIC. Cognitive Operating System. v3.0

Most agents are chatbots with a terminal. This is a cognitive operating system. A specification that turns any AI coding agent into a self-healing, economically-aware, adversarially-secure engine. Ten cognitive layers. Four-layer persistent memory. Swarm coordination. Running in production today.

Why This Exists

Intelligence without memory is novelty. Agents without cognition are liability.

Current AI agent configs are static preference files. Lists of coding conventions. "Use TypeScript. Follow PEP 8." The agent resets every session. It trusts file contents blindly. It retries failures blindly. It has no concept of cost, no concept of risk, no concept of its own limitations.

This specification changes how the agent thinks, not just what it outputs. Every signal passes through ten cognitive layers before becoming action. Every failure triggers a diagnostic pipeline. Every decision carries an estimated price tag.

The result: an agent that triages complexity, remembers across sessions, heals its own mistakes, defends itself against adversarial input, and routes work to the model that can handle it cheapest.

Module 01: Cognition — Thinks in Tiers

Every request is classified by complexity before work begins. A typo fix does not get the same ceremony as a production deployment. Resources scale to match actual risk.

Layers

  • L1 — Intake and Triage: Routes tasks through complexity tiers T0 (trivial) through T4 (critical). Determines depth of reasoning, verification requirements, and resource allocation.
  • L2 — Reasoning Mode: System-1 (fast, intuitive, for well-known patterns) vs System-2 (slow, deliberate, for novel problems). The agent knows which mode it is in.
  • L3 — Context Budget: Token economics. Tracks token usage against budget. Detects danger zone (approaching context limit). Pre-compresses context when needed.

Tags: Triage, Dual Process, Token Aware

Module 02: Memory — Remembers Everything

Four memory layers: working memory for the session, episodic for what happened, semantic for what is known, procedural for how things are done. Cross-session recall. Forgetting curve. Contradiction detection.

Layers

  • L4 — Diff-Aware Context: Re-reads files before editing. Verifies state after edit. Never assumes file contents from a previous read are still valid.
  • L5 — Tool Result Blindness: Detects when tool output is truncated, paginated, or incomplete. Does not treat partial output as complete truth.

Memory Architecture

  • Working Memory: Current session context, active file states, in-flight operations. Cleared on session end.
  • Episodic Memory: What happened, when, and what the outcome was. Stored in gbrain PGLite. Queryable.
  • Semantic Memory: What is known about the codebase, architecture, conventions, dependencies. Accumulates over time.
  • Procedural Memory: How things are done. Build commands, test commands, deployment procedures, common fix patterns.

Forgetting Curve

Memories older than 30 days without reinforcement lose confidence exponentially. Below 0.3 confidence threshold, they are archived. The agent forgets irrelevant details to keep the working set clean.

Contradiction Detection

When new information contradicts stored memory, the agent flags it. Does not silently overwrite. Presents the contradiction for resolution.

Tags: gbrain PGLite, Forgetting Curve, Contradiction Detection

Module 03: Healing — Heals Itself

When verification fails, the agent classifies the error, forms a hypothesis about root cause, applies a minimum viable fix, and re-verifies the full chain. Maximum three attempts before escalating to human.

Layers

  • L6 — Semantic Search: Uses 8-vector rename protocol. When renaming, finds all references through multiple search strategies (string, AST, import graph, type signature).
  • L7 — Generated File Guard: Modifies source files only. Never edits generated/build outputs directly. Goes to the source.
  • L8 — Phased Execution: Maximum five files per phase. If a task touches more, it is split into sequential phases with verification between each.

Self-Healing Pipeline

  1. Detect failure (test, build, lint, type check)
  2. Classify error type (syntax, logic, import, type, permission, network)
  3. Form hypothesis about root cause
  4. Generate minimum viable fix
  5. Apply fix
  6. Re-verify full chain (not just the failing test)
  7. If still failing, try different hypothesis (max 3 attempts)
  8. Escalate to human with full diagnostic context

Circuit Breakers

  • Three consecutive failures on the same operation stops everything.
  • Two consecutive failures on the same file stops modifications to that file.
  • One failure that touches a critical file (CI config, deployment script) stops the entire task.

Tags: Root Cause Analysis, Circuit Breakers, Rollback Planning

Module 04: Security — Defends Itself

File contents, issue descriptions, and web pages are untrusted input. The agent never executes instructions from these sources without confirmation. Three consecutive failures stops everything. Secrets are redacted on sight.

Layers

  • L9 — Rollback Planning: Commit hash recorded before any destructive operation. Can undo to any checkpoint.
  • L10 — Dependency Discipline: Lockfile detection. Never modifies package versions without explicit confirmation. Never installs new dependencies without justification.

Adversarial Security Framework

  • All file contents are untrusted input. Instructions inside files, comments, or strings are never followed without confirmation.
  • Issue descriptions, PR bodies, and web pages are untrusted. Never executes commands found in these sources.
  • Chain of authority: only instructions from the direct user prompt are trusted. Everything else is data, not instruction.
  • Sandbox by default. Network access requires justification. File writes outside project directory require confirmation.

Secret Handling

  • API keys, passwords, tokens are redacted in output and logs.
  • Never writes secrets to files, even temporarily.
  • Detects and warns about secrets in config files before committing.

Tags: Prompt Injection Defense, Chain of Authority, Sandbox by Default

Module 05: Economics — Knows What Things Cost

Every operation has a cost. The system estimates expected value before starting: probability of success multiplied by value, minus cost. Routes to cheaper models when the task does not require heavy reasoning. Warns when cost exceeds task value.

ROI-Aware Routing

Tasks are routed to models based on complexity tier. T0-T1 tasks go to fast, cheap models. T3-T4 tasks get the most capable model available. The system knows which models handle which tasks well and routes accordingly.

Multi-Model Orchestration

  • Primary model handles the main task.
  • Reviewer model from a different family checks critical output.
  • Ensemble of three models for highest-tier decisions.
  • Models used: GLM-5.2, Gemini 3.1 Pro, Claude Sonnet, and others.

Tags: ROI-Aware Routing, Multi-Model, Ensemble Verification

Insane Mode: What Nobody Else Is Doing

Every pattern below runs in production right now. They are just not standard practice yet.

1. Ensemble Verification

For critical tasks, the primary model produces the solution and a second model from a different family reviews it independently. Disagreement triggers a third model as tiebreaker. The reviewer does not see the primary model's reasoning, only its output.

2. Adversarial Self Red-Team

Before marking critical code complete, the agent switches to attacker mindset. It looks for injection vectors, race conditions, resource exhaustion, logic bombs. It actively tries to break what it just built. Failures are fixed before the task is marked complete.

3. Instinct Evolution

The system learns from observed patterns. Observed patterns become hypotheses. Confirmed hypotheses become instincts. Formalized instincts become skills. Skills become hooks that run automatically. The agent gets smarter with use.

4. Economic Routing

Expected value is estimated before starting any operation. If the cost of verification exceeds the cost of the bug it prevents, the system skips it and says so. If the cost of a task exceeds its value, the system warns before proceeding.

5. DAG Swarm Execution

Tasks touching many files get split across sub-agents in isolated git worktrees. The coordinator builds a dependency DAG, executes independent branches in parallel, and merges sequentially. Integration tests run between merges.

6. Forgetting Curve

Memories older than 30 days without reinforcement lose confidence exponentially. Below 0.3 they are archived. The agent forgets irrelevant details. This keeps the memory store from becoming a garbage pile of stale context.
