> Retrospective field note for 2025-12-22. Reconstructed in November 2026 from dated sources, not originally published on the archive date.

Markdown isn't the PDF. Source code isn't the page. The exported result is where the person encounters the work.

Following the GPT-5.2 release, artifact generation is an obvious place to apply a very old habit: look at what you made before sending it.

Render it, inspect it, correct it, render it again. Check the crowded page, not just the cover. On a website, check a narrow viewport and a scrolled state. Text overflowing a card won't necessarily stop a build. Neither will a header covering the first paragraph.

A screenshot doesn't answer every question. Try the keyboard path. Check reading order and contrast. If an effect moves, inspect its reduced-motion behaviour rather than assuming a still image proves accessibility.

Fix the layout rule where possible. Shrinking one paragraph until it fits can leave the same problem waiting for the next content update.

This doesn't need to become an elaborate ceremony for every tiny change. Match the check to the risk. But if the deliverable is visual, skipping the visual check is an odd place to save time. The source can be perfectly valid while the result is plainly wrong.
