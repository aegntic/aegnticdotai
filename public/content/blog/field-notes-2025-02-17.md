*Retrospective reconstruction of the week beginning 2025-02-17, written on 16 November 2026. This is not a claim of publication at the time.*

Operator's January preview raised a very practical interface problem. How much of the task can someone hand over before the assistant needs them again?

Asking about every click turns the user into a remote control. Asking after something irreversible has happened is too late. The boundaries need to be settled before the workflow reaches them.

Preparing a draft is one stage. Sending it is another. Finding an item does not settle the purchase. Opening access to a service changes more than reading its settings. The agent should know which stage the request covers and do the routine preparation without making the person supervise it.

When a decision is needed, arrive ready. Explain the actual choice, its consequences and what is waiting on the answer. Do not send a vague question that forces the user to investigate the task again.

The same care applies to recovery. Preserve the previous state where possible. If the result is uncertain, check it. A duplicate submission is a particularly bad reward for someone who delegated the work to save time.
