> Retrospective field note for 2025-07-07. Reconstructed in November 2026 from dated sources, not originally published on the archive date.

Gemini CLI landed on 25 June. AI in the terminal makes sense to me: the files, commands and tests are already there. Moving between a chat window and the actual project is mostly friction.

But a terminal can tell you the build passed while the header is sitting on top of the article. Both things can be true. That's the gap worth paying attention to.

“Fix the header” means the reader can see the content. It means the menu still works on a phone. It means scrolling doesn't turn the page into a game of chasing the navigation. Editing a stylesheet is one step towards that result, not the result itself.

I'd want the failure reproduced first, then the change, then the existing checks, then a look at the page. In that order. If the task also needs a dependency upgrade, explain why. Otherwise leave it alone.

The appeal of a terminal agent is that it can do the work where the work lives. The finish line still belongs to the person using the thing. Show the page working. A list of successful commands is useful evidence, but it cannot see through an overlapping header.
