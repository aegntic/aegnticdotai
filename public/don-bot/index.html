How it works

Simple from your seat. Serious underneath.

You see plain goals, clean status, and fast approvals. Open any section below for the engineering behind the reliability.

How long builds recover after crashes or restarts

Every tool step and team decision commits to a local SQLite WAL spine with idempotent once() memoization. If power drops or a worker dies mid-run, Don-Bot picks up from the exact unfinished step rather than replaying side effects.

Single-writer file leases prevent concurrent workers from overwriting one another, while automatic context handoffs at 10%, 20%, and 30% usage keep memory sharp across long jobs.

How five specialists coordinate without file collisions

One Lead Orchestrator coordinates four durable specialists (API Keeper, Pipeline Forge, Browser/UI QA, and Memory Curator) over structured SQLite rooms instead of spawning dozens of ephemeral subagents.

Before touching code, the roster runs a three-round architecture alignment to lock interfaces and file ownership, tuning each role's model tier and reasoning depth per task.

How credentials stay hidden and bad actions get caught

High-impact tool calls pass through a 300ms calibrated System-One gate before execution, catching risky actions and verifying quotes directly against room logs.

API keys live inside a Blind Vault that injects secrets only inside the execution boundary, scrubs them from output, and requires a separate read-only Sibling Verifier to confirm claims before marking work complete.

How pocket approvals stay synced with the desktop workspace

In Personal Mode, Don-Bot bridges your own Telegram and WhatsApp sessions with paced outbound limits and topic organization, surfacing short approval cards whenever your input is needed.

On desktop, a three-pane cockpit maps every screen button 1:1 to agent tools, lets you watch live virtual display runs, and switches directly into any specialist lane.
